# 노트북 과제 키트

강의에서 받은 주피터 노트북을 **직접 실행해 보고, 그 결과로 보고서를 만들어 제출**하는
과제를 처리한다. 네 단계이고, 각 단계는 앞 단계의 산출물만 있으면 독립적으로 다시 돌릴 수 있다.

```
① 준비      ② 실행            ③ 보고서            ④ 문서화
환경·설정 →  노트북 실행·수정 →  마크다운 작성 →   .docx 변환·검증
            실행결과/          보고서/            보고서_docx/
```

스크립트는 모두 `${CLAUDE_PLUGIN_ROOT}/scripts/` 에 있다. 작업 폴더가 어디든,
운영체제가 무엇이든 동작한다. **항상 사용자의 작업 폴더에서 실행한다.**

## 시작하기 전에 확인할 것

1. **작업 폴더가 맞는가** — `ts_kit.config.json` 이 있는 폴더가 기준이 된다. 없으면 ①부터 시작한다.
2. **이름·학번이 채워져 있는가** — 보고서 표지에 들어간다. 비어 있으면 **반드시 사용자에게 물어본다.**
   추측하거나 예시 값으로 채우지 않는다. 남의 학번으로 제출되는 사고가 실제로 일어난다.
3. **몇 번째 과제인가** — `assignment.number` 가 산출물 이름 앞에 `과제1_` 처럼 붙는다.
   같은 폴더에서 다음 과제를 해도 섞이지 않는다. 모르면 1 로 둔다.
4. **파이썬 가상환경을 쓰는가** — 권장한다. 노트북이 최신 라이브러리와 충돌해 버전을 바꿔야
   할 때가 많은데, 가상환경이면 다른 작업에 영향을 주지 않는다.

## ① 준비

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/setup_env.py" --name "홍길동" --id "20260001" \
    --repo "https://github.com/<계정>/<저장소>"
```

작업 폴더·설정 파일·`fixes.py` 를 만들고, 빠진 패키지를 설치하고, 한글 폰트를 확인한다.
폰트가 없다고 나오면 그래프의 한글이 깨지므로 사용자에게 알린다(맥 AppleGothic, 리눅스 NanumGothic).

## ② 노트북 내려받기와 실행

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/fetch_notebooks.py"
python "${CLAUDE_PLUGIN_ROOT}/scripts/run_notebooks.py"
```

노트북 하나만 시험할 때는 이름 일부를 인자로 준다: `run_notebooks.py Differencing`

**오류는 정상이다.** 강의 노트북은 보통 몇 년 전 라이브러리 기준이라, 최신 pandas·statsmodels
에서 깨지는 셀이 반드시 나온다. 처리 원칙:

- **원본 노트북 파일은 절대 고치지 않는다.** 수정은 작업 폴더의 `fixes.py` 에만 적는다.
  `{노트북명: [(셀번호, 원본문자열, 바꿀문자열, 이유), ...]}` 형식이다.
- 이유는 **오류 메시지와 원인을 같이** 적는다. 이게 그대로 보고서의 "오류 및 수정 내역"이 되고,
  교수님이 보기에 가장 점수가 되는 부분이다.
  예: `"TypeError: NDFrame.fillna() got an unexpected keyword argument 'method' — pandas 3.0에서 fillna(method=) 삭제"`
- 코드를 안 고치고 환경만 조치했다면(예: 패키지 설치) old 와 new 를 같게 두고 이유만 적는다.
- 고친 뒤 그 노트북만 다시 돌려 확인한다. **오류 0이 될 때까지 반복한다.**

결과는 `실행결과/<노트북명>/` 에 셀별 출력(`cellNN.txt`), 그림(`cellNN_figK.png`),
요약(`summary.md`)으로 쌓인다.

## ③ 보고서 작성 — 이 단계가 핵심이다

`실행결과/*/summary.md` 를 읽고, 노트북마다 `보고서/과제<번호>_<이름>.md` 를 쓴다. 이건 스크립트가
대신 못 한다. **실행 결과를 실제로 읽고, 무엇이 나왔는지 해석해서 써야 한다.**

문서 하나의 구조:

````markdown
# <노트북명> — <한 줄 주제>

- **출처 슬라이드** : <강의안 쪽수>
- **사용 데이터** : <무엇을, 어느 기간, 몇 건>
- **실습 목표** : <이 실습으로 무엇을 확인하는가>

---

## 목차
1. [첫 번째 단계](#s1)
...

<a id="s1"></a>

## 1. <단계 이름>

### 코드 설명
<이 코드가 무엇을 하는지 말로. 소스코드 전문은 싣지 않는다.>

### 실행 결과
```
<cellNN.txt 의 출력>
```
![설명](../실행결과/<노트북명>/cellNN_figK.png)

### 결과 정리
<그래프·숫자가 무엇을 뜻하는지. 값을 직접 인용하며 설명한다.>
````

지켜야 할 것:

- **그림 경로는 `../실행결과/...` 상대경로로 쓴다.** ④에서 이 경로를 따라가 그림을 넣는다.
  경로가 틀리면 docx 에 그림이 빠지고, 검증 단계에서 잡힌다.
- **소스코드 전문을 붙여넣지 않는다.** 무엇을 하는 코드인지 설명하고, 출력과 그림을 보인다.
  코드만 길게 붙은 보고서는 읽히지 않는다.
- **숫자를 인용해서 해석한다.** "자기상관이 있음" 이 아니라 "p-value 가 0.0016 으로 0.05 보다
  작아 자기상관이 있다고 판정됨" 처럼 쓴다.
- **문체를 하나로 통일한다.** 사용자가 원하는 문체를 먼저 확인하고, 전 문서에 동일하게 적용한다.
- **파일 이름 앞에 과제 번호를 붙인다** — `보고서/과제1_00_ACF.md`. 실행결과 폴더에는 붙이지
  않는다. 같은 노트북 결과를 다음 과제에서도 쓰기 때문이다.
- 마지막에 `보고서/과제<번호>_00_목차.md` 를 만든다. 맨 위에 **"과제 N — 제목"**, 이름·학번,
  과제 개요, 각 문서로 가는 링크(`[이름](과제1_00_ACF.md)` 형식 — ④에서 `.docx` 링크로 자동
  변환된다), 오류·수정 종합표를 넣는다.

문서가 여러 개면 **병렬로 나눠 쓰는 편이 빠르다.** 다만 문체·구조가 갈라지기 쉬우므로,
먼저 한 개를 완성해 사용자에게 확인받고 그걸 본보기로 삼아 나머지를 쓴다.

## ④ Word 변환과 검증

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/batch_docx.py"
python "${CLAUDE_PLUGIN_ROOT}/scripts/verify_docx.py" --render
```

변환기가 옮기는 것: 제목 3단계, 목록, 표, 코드블록, 인용문, 그림(본문 폭에 맞춰 축소),
구분선, 문서 안 목차 링크(Word 북마크), 문서 사이 링크(`.md` → `.docx` 자동 변환).

검증기가 보는 것: 그림 수, 목차 링크 연결 여부, 링크 대상 파일 존재, 한글 본문 유실.
`--render` 를 주면 Word(윈도우) 나 LibreOffice 로 실제로 열어 페이지 수와 표시된 그림까지 확인한다.

**검증에서 "문제 0건" 이 나올 때까지 끝난 게 아니다.** 흔한 원인:

| 증상 | 원인 | 조치 |
|---|---|---|
| 그림 수가 모자람 | 보고서의 그림 경로가 틀림 | `보고서/*.md` 의 `../실행결과/...` 경로 확인 |
| 목차 링크 끊김 | `<a id="s1"></a>` 앵커 누락 | 각 절 제목 바로 앞에 앵커를 넣는다 |
| 본문 누락 | 변환기가 못 읽는 문법 | 해당 문단의 마크다운을 단순하게 고친다 |

글꼴·본문 크기·그림 최대 폭·절마다 페이지 나눔은 `ts_kit.config.json` 의 `docx` 항목에서 바꾼다.

## 자주 묻는 것

- **주식 데이터가 안 받아진다** — `yfinance` 는 네트워크와 야후 응답에 따라 실패한다. 잠시 뒤
  다시 시도하고, 계속 실패하면 해당 노트북만 건너뛴 뒤 사용자에게 알린다.
- **그림의 한글이 네모로 나온다** — 한글 폰트 문제다. `setup_env.py` 출력의 폰트 줄을 확인한다.
- **다른 과목에도 쓰고 싶다** — 새 폴더에서 ①을 다시 하면 된다. 설정은 폴더마다 따로 있다.
- **다음 과제는 어떻게 하나** — 같은 폴더에서 `setup_env.py --assignment 2` 로 번호만 올리면
  된다. 이미 받아 둔 노트북과 실행 결과를 그대로 쓰고, 보고서만 `과제2_...` 로 새로 쌓인다.

## 하지 말 것

- 실행해 보지도 않고 결과를 지어내지 않는다. 보고서의 숫자는 전부 `실행결과/` 에서 온 것이어야 한다.
- 오류가 난 셀을 조용히 지우지 않는다. 고치고 그 내역을 남기는 것이 과제의 일부다.
- 강의안 PDF 처럼 저작권이 있는 자료를 공개 저장소에 올리지 않는다.
